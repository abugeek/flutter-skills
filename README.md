# Flutter knowledge & Claude Code skills

Up-to-date, source-verified Flutter guidance packaged as [Claude Code skills](https://docs.claude.com/en/docs/claude-code/skills), plus free scripts that collect it (no AI tokens spent on scraping).

## Skills (`.claude/skills/`)

| Skill | Covers |
|---|---|
| `flutter-dart-style` | Modern Dart 3.13 / Flutter 3.47 code: primary constructors, dot shorthands, patterns, sealed classes, widget conventions, lints |
| `flutter-architecture` | Official Flutter layering (View/ViewModel → Repository/Service), folder layout, DI, Result/Command, data & persistence, day-one setup, scaling teams |
| `flutter-state-management` | Choosing Riverpod 3 / Bloc 9 / official MVVM / built-ins; per-library references loaded on demand |
| `flutter-testing` | Test pyramid, fakes vs mocks, Alchemist goldens, Patrol 4 E2E, widget previews |
| `flutter-performance` | Rebuilds, lists/slivers, images, opacity/saveLayer, isolates, app size |
| `leancode-flutter` | Router into the LeanCode glossary/blog archive for everything else |

Every skill states the date and versions it was verified against. Code examples compile: see `checks/`.

## Using the skills
Copy `.claude/skills/<name>/` into your project's `.claude/skills/` (or `~/.claude/skills/` for all projects). Claude loads a skill's SKILL.md only when a task matches its description, and reference files only when needed.

## Refreshing: one command, no AI tokens
```sh
python3 update.py            # fetch docs + pub.dev → diff → regenerate → stale-version scan → compile checks
```
It writes **`UPDATE_REPORT.md`**: failing compile checks, skills mentioning outdated major versions, package bumps, and exactly which source docs changed. The model only needs to read that report (and the changed files it lists). If it says "Nothing to do", no AI time is needed at all.

Generated automatically (don't hand-edit): `generated/package-versions.md`, `generated/flutter-breaking-changes.md`, `.claude/skills/flutter-skills-index/SKILL.md`.

Flags: `--no-fetch` (regenerate from local sources), `--no-checks`. LeanCode archive: `.venv/bin/python scrape.py glossary|blog` (needs `pip install beautifulsoup4 markdownify` once).

## Evaluating skills cheaply
`evals/checks.json` holds regex checks per test prompt (`"in": "code"` to search only code blocks). After running test answers into a workspace: `python3 grade.py evals/checks.json <workspace>/iteration-N`. Grading is instant and costs no tokens. Only the answer-generation runs cost tokens: reuse the no-skill baselines and re-run with-skill only.

## Automation (GitHub Actions, free for public repos)
`.github/workflows/update.yml` runs `update.py` every Monday (and on demand from the Actions tab). It commits regenerated files, and when something needs a human or AI look (failing compile check, outdated version in a skill, changed docs), it opens or updates a single **"Skills update report"** issue. No AI runs in CI.
